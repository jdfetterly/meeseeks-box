# Chat Brief: Inbox Page

You are helping define the Inbox page for Meeseek Box.

## Product Direction

Inbox should contain operational attention only.

It should handle:

- approvals
- failures
- blocked work
- missed schedules
- other runtime attention

It should not be the place for reviewing completed outputs.

## Locked Decisions

- Review Queue is separate.
- Inbox is for intervention, not evaluation.
- The app should feel project-aware, but Inbox still focuses on operational urgency.

## What This Chat Should Produce

Define the Inbox page:

- item categories
- filtering
- severity/priority handling
- actions
- how items link back to projects, work, runs, schedules, or workspace state

## Please Cover

- what categories belong in Inbox
- what metadata should be shown
- direct action vs link-out behavior
- approval handling
- failure handling
- blocked-work handling
- schedule issue handling
- resolved items behavior

## Constraints

- Keep it distinct from Review Queue.
- Avoid turning it into a generic activity feed.

## Output Format

Return:

1. Inbox goals
2. Item categories and filters
3. Action model
4. Edge cases
5. Acceptance criteria
