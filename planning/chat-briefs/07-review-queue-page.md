# Chat Brief: Review Queue Page

You are helping define the Review Queue for Meeseek Box.

## Product Direction

Review Queue is where completed outputs wait for human judgment.

It is not the same as Inbox. Inbox is for operational attention. Review Queue is for evaluating agent work.

## Locked Decisions

- Review Queue and Inbox are separate surfaces.
- Completed outputs should go to Review Queue by default.
- Review is a core part of the loop:
  - delegate
  - review
  - adjust
- Review should be project-aware.

## What This Chat Should Produce

Define the Review Queue page and behavior:

- what appears there
- how items are summarized
- what actions are available
- how a user judges or resolves an item
- how review connects back to projects and work items

## Please Cover

- review item anatomy
- artifact/output presentation
- summary vs deep inspection
- actions:
  - mark reviewed
  - request changes
  - reopen follow-up work
  - jump to project/work/workspace context
- review states
- what should never appear in Review Queue

## Constraints

- Keep this focused on judgment, not operational cleanup.
- Make it obvious why the item is here and what to do next.

## Output Format

Return:

1. Review Queue goals
2. Review item model
3. Review actions and transitions
4. Edge cases
5. Acceptance criteria
